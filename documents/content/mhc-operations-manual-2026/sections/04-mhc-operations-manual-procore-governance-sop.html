Status: Draft v0.1 Command Owner: COO (XO) Backup Owner: Chief Superintendent (Master Chief) Primary Reviewer: PM Lead Final Approver: CEO (CO)

1. Mission Purpose

Define one enforceable Procore governance workflow that standardizes project setup, access control, RFI/submittal routing, and closeout sign-off discipline.

2. Command Ownership and Authority

  • Project setup execution authority: PE
  • Project setup approval authority: PM
  • Project activation authority: XO (COO)
  • Enterprise admin control authority: HR and XO
  • Final command escalation authority: CO

Command alignment:

  • PMs and PEs formally report through XO.
  • PM/PE execution supports Master Chief field mission objectives.
  • CHENG may escalate critical safety/compliance platform issues directly to CO.

3. Required Inputs

  • Executed contract and scope summary
  • Approved estimate baseline and assumptions package
  • Project schedule baseline
  • Contact registry (owner, architect, engineer, key subcontractors)
  • Safety and compliance setup requirements

4. Required Outputs

  • Procore project created and permissioned
  • Active module checklist completed
  • RFI and submittal routing activated
  • Project communication standards published to internal team
  • Project readiness confirmation logged for Monday control meeting

5. SOP Steps

Step 1 - Project Setup (PE)

  • Create project shell in Procore.
  • Populate project metadata and contract identifiers.
  • Configure folder structures and document naming standards.
  • Load contact directory and role mapping.

Step 2 - PM Review and Approval

  • PM reviews structure, cost-code alignment, and routing.
  • PM confirms readiness of log workflows (RFI, submittal, correspondence).
  • PM records approval before activation request.

Step 3 - XO Go-Ahead

  • XO validates setup integrity and command readiness.
  • XO authorizes project activation.
  • If gaps remain, setup is returned to PE/PM with corrective actions.

Step 4 - Access and Permissions Governance

  • HR/XO maintain admin rights and account lifecycle controls.
  • Role-based access is enforced by least privilege.
  • Elevated access requests require XO approval.

Step 5 - RFI and Submittal Workflow

  • Field crew/subcontractor clarification request is logged through PE.
  • PE prepares documentation and routing package.
  • PM approves outgoing RFI/submittal.
  • Approved package is sent to architect/engineer.
  • Response is logged and distributed to relevant field/office roles.

Step 6 - Ongoing Controls

  • PM conducts weekly governance check for open-item aging.
  • PE ensures log integrity and document completeness.
  • Master Chief validates field-facing items are actionable.

6. Controls and Thresholds

  • No project may begin active workflow without PM approval and XO activation.
  • No external RFI/submittal may be issued without PM approval.
  • Permission exceptions require XO authorization.
  • Closeout requires digital sign-off in Procore before external release.

7. KPI and Review Cadence

Weekly (Monday 9:00 AM control meeting):

  • Open RFIs by aging bucket
  • Open submittals by aging bucket
  • Permission exceptions count
  • Unresolved governance exceptions

Quarterly audit:

  • Workflow compliance rate
  • Routing accuracy rate
  • Documentation completeness score

8. Evidence and Record Location

Primary system of record:

  • Procore project logs and approval history

Supporting records:

  • Meeting decisions and escalations in weekly operations minutes appendix
  • Exception logs retained in operations control archive

9. Escalation Path

Standard path:

  • PE/PM -> XO -> CO

Exception path:

  • CHENG may escalate directly to CO for mission-critical safety/compliance risk.

10. Non-Compliance Response

  • First breach: documented corrective action and deadline.
  • Repeat breach: XO-led review and role-specific control retraining.
  • Critical breach: immediate command review with potential CO intervention.
