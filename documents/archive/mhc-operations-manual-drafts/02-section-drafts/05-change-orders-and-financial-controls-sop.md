# MHC Operations Manual - Change Orders and Financial Controls SOP

Status: Draft v0.1
Command Owner: COO (XO)
Backup Owner: Acting CFO function (currently XO)
Primary Reviewer: PM Lead
Final Approver: CEO (CO)

## 1. Mission Purpose

Establish strict change-order and financial control discipline using single-change-order thresholds, SAGE100 synchronization, and clear authority routing.

The same control thresholds apply to both initial proposals/estimates governed by the Sales Guide and post-contract change orders.

## 2. Command Ownership and Authority

Approval authority by single change-order amount:

- PM authority: less than 25,000
- XO authority required: 25,000 to 49,999
- CO authority required: 50,000 and above

Related command roles:

- PE prepares backup package and documentation.
- PM is accountable for job-level control discipline.
- CPCO is consulted when estimate assumptions or preconstruction exposure drives change risk.
- CFO function is advisory only and currently carried by XO.

## 3. Required Inputs

- Proposed change description and justification
- Scope impact statement
- Cost breakdown and supporting quotes
- Schedule impact estimate
- Contract reference and entitlement basis
- PM recommendation memo

## 4. Required Outputs

- Approved or rejected change-order decision
- Updated cost and forecast records
- SAGE100 posting-ready package
- Updated project control dashboard status
- Escalation record when thresholds trigger XO/CO review

## 5. SOP Steps

### Step 1 - Intake and Draft (PE)

- PE logs change request and assembles supporting documentation.
- PE tags risk type: scope, schedule, safety/compliance, vendor, or design.
- PE routes package to PM for decision prep.

### Step 2 - PM Review and Validation

- PM verifies entitlement, pricing basis, and schedule consequence.
- PM confirms package completeness and determines threshold lane.
- PM records recommendation.

### Step 3 - Threshold Routing

- If amount is less than 25,000: PM may approve.
- If amount is 25,000 to 49,999: PM forwards to XO for approval.
- If amount is 50,000 or greater: PM/XO forward to CO for final approval.

### Step 4 - SAGE100 Synchronization

- Approved changes are prepared for SAGE100 posting.
- Cost code alignment is validated prior to posting.
- Job Cost and purchasing updates are reconciled to approved change package.

### Step 5 - Communication and Implementation

- PM issues implementation direction after approval.
- PE updates logs and field-facing documentation.
- Master Chief and field leadership receive scope change briefing when execution is impacted.

## 6. Controls and Thresholds

- Threshold is based on each single change order, not cumulative stack value.
- No work execution against unapproved threshold-exceeding change package.
- No SAGE100 update without approved authority record.
- All threshold decisions must be auditable.

## 7. KPI and Review Cadence

Weekly (Monday 9:00 AM control meeting):

- Pending change orders by threshold lane
- Approval cycle time
- Aging of unapproved changes
- Approved vs implemented variance count

Quarterly audit:

- Threshold compliance rate
- Posting accuracy to SAGE100
- Cost variance trend by project

## 8. Evidence and Record Location

Primary evidence:

- Procore change-order log and approval trail

Financial evidence:

- SAGE100 posting records and reconciliation packets

Operational evidence:

- Weekly operations meeting decisions and action items

## 9. Escalation Path

Standard path:

- PE -> PM -> XO -> CO (by threshold)

Exception path:

- CHENG may escalate directly to CO for safety/compliance risk.
- CPCO may escalate directly to CO for preconstruction or strategic exposure risk.

## 10. Non-Compliance Response

- First breach: documented correction and responsible-owner retraining.
- Repeat breach: XO corrective review with command action plan.
- Severe breach: CO command review and temporary authority restriction as needed.
