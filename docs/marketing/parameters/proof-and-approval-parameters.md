# Proof and Approval Parameters (Shared Evidence Baseline)

**Category:** Marketing - Strategy Baseline  
**Last Updated:** July 31, 2026  
**Status:** Active

## Purpose

Define the shared proof gates, approval thresholds, and release rules used whenever MH publishes project-facing communication or reuses stakeholder recap content across marketing and sales surfaces.

Use this file when deciding whether content is strong enough, approved enough, and low-risk enough to be published, repurposed, or held.

## Canonical Proof Parameters

### Evidence Gates

- Publish only updates tied to actual milestones, visible field conditions, or approved stakeholder facts.
- Prefer completed-scope photos, milestone notes, approved project facts, verified outcomes, and stakeholder-approved summaries.
- Do not publish speculative completion claims, internal-only assumptions, or performance claims that cannot be defended later.

### Hold Conditions

- Hold the content when approvals are incomplete.
- Hold the content when field conditions are still moving and the proof set may become inaccurate.
- Hold the content when the asset exposes privacy, controlled-access, or active-jobsite risk.
- Hold the content when a lower-risk proof set is available and would still communicate the point clearly.

### Public-Sector and Sensitive Work

- For government and grant-funded work, adapt release decisions to project security sensitivity before publishing anything externally.
- Apply documented confidentiality review gates when project details reach confidential or top-secret thresholds.
- Release only approved, non-sensitive details on public surfaces.
- When uncertainty exists, choose the lower-risk release path and wait for explicit approval.

## Canonical Approval Parameters

### Minimum Approval Checks

1. Brand terminology matches MH standards.
2. Claims are evidence-backed and project-approved.
3. Channel choice, cadence choice, and content length fit the project context.
4. Any exception from baseline is documented with reason.

### Cross-Guide Reuse Rule

- If sales follow-up content, proposal recap language, or owner-approved updates may appear on marketing surfaces later, verify the proof set again before reuse.
- Approval for owner communication does not automatically equal approval for public release.
- Marketing and sales should both defer to this file when proof quality or release readiness is in question.
