# MH Construction Safety Terminology Glossary

**Status:** Canonical

## Purpose

This glossary standardizes safety-program terminology across website content,
generated manuals, forms, dashboard workflows, and project documentation.

Use this file as the canonical reference when naming or describing MISH,
APP, SSSP, SDS/MSDS, and Toolbox Talk operations.

## Canonical Terms

### MISH

- **Expansion:** MH Construction Industrial Safety & Health Program.
- **Role:** Enterprise safety framework and canonical written program baseline.
- **Usage rule:** When first used in a document, expand once, then use `MISH`.

### APP

- **Expansion:** Accident Prevention Plan.
- **Relationship to MISH:** MISH is MH Construction's branded APP framework.
- **Usage rule:** APP can be used as a supporting term after MISH is defined.

### SSSP

- **Expansion:** Site Specific Safety Plan.
- **Relationship to MISH:** MISH is the backbone for every SSSP.
- **Authoring rule:** Each SSSP must be unique to the specific project scope,
  hazards, sequencing, site conditions, and contract requirements.
- **Traceability rule:** Each SSSP control should map back to MISH chapters,
  forms, and project-required addenda.

### SDS / MSDS

- **SDS expansion:** Safety Data Sheet (current regulatory convention).
- **MSDS expansion:** Material Safety Data Sheet (legacy/common reference).
- **MH rule:** Public and marketing copy should prefer `Safety Data Sheets
(SDS/MSDS)` for SEO and clarity, while preserving regulatory accuracy.
- **Availability rule:** Maintain SDS/MSDS access in controlled internal systems and
  physical field sets (truck binders and Mobile Command Center's/office trailers).
- **Upload status rule:** If SDS/MSDS libraries are not yet ready for document-pipeline upload,
  preserve naming and workflow compatibility so later publication does not require terminology rewrites.

### Toolbox Talks

- **Definition:** Daily field safety briefings used to reinforce hazard controls,
  work sequencing precautions, and incident-prevention focus.
- **Freshness standard:** Maintain a full-year daily rotation and align topics
  with OSHA hazard seasons.
- **Repeat rule:** Topic repeats are acceptable when seasonally relevant and
  risk-driven; repetition for active hazards is a required control, not drift.
- **Execution rule:** Toolbox Talk content should be mapped to active project
  risks and linked to applicable MISH chapters/forms where possible.
- **Upload status rule:** If Toolbox Talk libraries are pending upload, keep topic names,
  risk tags, and references stable so future publication can plug in without cross-manual drift.

### Field Operations

- **Definition:** Daily project execution layer where crew-level safety,
  quality, and production controls are applied in real time.
- **Required safety controls:**
  - Daily Toolbox Talk before shift start.
  - Current Safety Data Sheets (SDS/MSDS) availability for all active materials
    via controlled internal systems and physical field copies.
- **Operational expectation:** No field task proceeds without both controls
  being in place and verifiable.

## Program Freshness Standard

To prevent staleness and maintain field relevance:

- Maintain current Safety Data Sheets (SDS/MSDS) access for all active
  materials used on site.
- Maintain a daily Toolbox Talk library spanning all days of the year and
  aligned to OSHA hazard seasons.
- While upload publication is pending, maintain canonical naming and structure so
  the libraries can be added to the document pipeline without refactoring downstream guides.
- Require superintendent/crew-level confirmation that daily talk topics match
  the day's actual site conditions and work plan.
- Treat stale, non-risk-based repetition as a corrective-action trigger.
- Accept intentional hazard-season topic repeats when risk conditions warrant.

## Implementation Notes

- Prefer MISH-first wording in safety surfaces.
- Use APP as contextual framing when speaking with external stakeholders,
  clients, insurers, and compliance reviewers.
- Use SSSP language for project-level controls and pre-task execution plans.
